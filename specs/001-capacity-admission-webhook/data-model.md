# Data Model: Capacity Admission Webhook

**Phase**: 1 (Design) | **Date**: 2026-07-26

This document defines the entities, CRD schemas, state machines, and
validation rules for the capacity admission webhook.

---

## Entities

### 1. ClusterCapacity (CRD)

**Purpose**: Aggregated cluster supply — the total allocatable CPU and RAM
across all nodes, maintained by the Node Capacity Controller.

**Scope**: Cluster-scoped singleton (enforced by convention: a single instance
named `cluster-capacity`).

**Group/API**: `emergency-ration.dev/v1`

```rust
#[derive(CustomResource, Debug, Clone, Deserialize, Serialize, JsonSchema)]
#[kube(
    group = "emergency-ration.dev",
    version = "v1",
    kind = "ClusterCapacity",
    namespaced = false,  // cluster-scoped
    status = "ClusterCapacityStatus",
    shortname = "cc",
)]
pub struct ClusterCapacitySpec {
    // Supply-side CRD: spec is intentionally minimal.
    // The singleton instance name is "cluster-capacity".
    // No user-configurable fields — this CRD is controller-written.
}

#[derive(Debug, Clone, Default, Deserialize, Serialize, JsonSchema)]
pub struct ClusterCapacityStatus {
    /// Total allocatable CPU across all nodes, in milli-CPUs.
    pub total_allocatable_cpu_milli: i64,
    /// Total allocatable memory across all nodes, in bytes.
    pub total_allocatable_memory_bytes: i64,
    /// Number of nodes counted.
    pub node_count: i32,
    /// Timestamp of the last capacity recomputation (RFC 3339).
    pub last_updated: String,
}
```

**CRD YAML** (generated by `ClusterCapacity::crd()`):

```yaml

metadata:
  name: clustercapacities.emergency-ration.dev

          type: object

              type: object
              properties: {}
            status:
              type: object
              properties:
                totalAllocatableCPUMilli:
                  type: integer
                  format: int64
                totalAllocatableMemoryBytes:
                  type: integer
                  format: int64
                nodeCount:
                  type: integer
                  format: int32
                lastUpdated:
                  type: string
```

**Validation rules**:
- `totalAllocatableCPUMilli` ≥ 0.
- `totalAllocatableMemoryBytes` ≥ 0.
- `nodeCount` ≥ 0.
- `lastUpdated` must be a valid RFC 3339 timestamp.

**State transitions**:
```
[empty] → (controller startup, first node list) → [populated]
[populated] → (node added/removed) → [populated, updated]
[populated] → (all nodes removed) → [populated, zeros]
```

### 2. Allocation (CRD)

**Purpose**: Aggregated cluster demand — current allocation and the budget
ceiling, maintained by the Allocation Controller. Carries the user-configurable
budget percentage in its `spec`.

**Scope**: Cluster-scoped singleton (instance named `cluster-allocation`).

**Group/API**: `emergency-ration.dev/v1`

```rust
#[derive(CustomResource, Debug, Clone, Deserialize, Serialize, JsonSchema)]
#[kube(
    group = "emergency-ration.dev",
    version = "v1",
    kind = "Allocation",
    namespaced = false,
    status = "AllocationStatus",
    shortname = "alloc",
)]
pub struct AllocationSpec {
    /// Maximum allowed allocation as a percentage of total allocatable
    /// capacity (0–100). Applied to both CPU and RAM.
    #[schemars(range(min = 0, max = 100))]
    pub budget_percent: i32,
}

#[derive(Debug, Clone, Default, Deserialize, Serialize, JsonSchema)]
pub struct AllocationStatus {
    /// Currently allocated CPU, in milli-CPUs (sum of pod requests).
    pub allocated_cpu_milli: i64,
    /// Currently allocated memory, in bytes (sum of pod requests).
    pub allocated_memory_bytes: i64,
    /// Budget ceiling for CPU, in milli-CPUs
    /// (= floor(totalAllocatableCPUMilli * budgetPercent / 100)).
    pub ceiling_cpu_milli: i64,
    /// Budget ceiling for memory, in bytes.
    pub ceiling_memory_bytes: i64,
    /// Utilisation ratio for CPU (allocated / ceiling), 0.0–1.0+.
    pub utilization_percent_cpu: f64,
    /// Utilisation ratio for memory.
    pub utilization_percent_memory: f64,
    /// Timestamp of the last allocation recomputation.
    pub last_updated: String,
}
```

**CRD YAML** (generated by `Allocation::crd()`):

```yaml

    - name: v1
      served: true
      storage: true
      subresources:
        status: {}
      schema:
        openAPIV3Schema:
          type: object
          properties:
            spec:
              type: object
              required: ["budgetPercent"]
              properties:
                budgetPercent:
                  type: integer
                  format: int32
                  minimum: 0
                  maximum: 100
            status:
              type: object
              properties:
                allocatedCPUMilli:
                  type: integer
                  format: int64
                allocatedMemoryBytes:
                  type: integer
                  format: int64
                ceilingCPUMilli:
                  type: integer
                  format: int64
                ceilingMemoryBytes:
                  type: integer
                  format: int64
                utilizationPercentCPU:
                  type: number
                  format: double
                utilizationPercentMemory:
                  type: number
                  format: double
                lastUpdated:
                  type: string
```

**Validation rules**:
- `spec.budgetPercent`: integer 0–100 (enforced by CRD schema `minimum`/`maximum`).
- `status.allocatedCPUMilli` ≥ 0.
- `status.allocatedMemoryBytes` ≥ 0.
- `status.ceilingCPUMilli` ≥ 0 (= 0 when budget is 0% or cluster has no nodes).
- `status.ceilingMemoryBytes` ≥ 0.

**State transitions**:
```
[no spec] → (user creates Allocation CR with budgetPercent) → [configured]
[configured] → (controller computes allocation) → [configured, status populated]
[configured, populated] → (pod created/deleted/updated) → [status updated]
[configured, populated] → (user changes budgetPercent) → [ceiling recomputed]
```

### 3. Admission Decision (transient, not persisted)

The admission decision is a transient computation, not a stored entity. It is
the output of the webhook handler for a single `AdmissionReview` request.

**Inputs**:
- `AdmissionRequest<V1Pod>`: the pod being created or updated.
- Cached `Allocation` status (from reflector): current allocation, ceiling,
  freshness timestamp.
- Cached `ClusterCapacity` status (from reflector): total allocatable (for
  computing ceilings if the Allocation CRD hasn't been updated yet).

**Computation**:
1. Extract resource requests from the incoming pod spec.
2. Resolve requests using Kubernetes defaulting: if a container has limits but
   no requests, `requests = limits` (per spec edge case + FR-005).
3. Sum requests across all containers in the pod → `podRequestCPU`,
   `podRequestMemory`.
4. For updates: compute the delta (new requests − old requests) and evaluate
   against the budget, not the full new request amount (FR-004, acceptance
   scenario 5).
5. Compare: `currentAllocation + podRequest` vs `ceiling` for each resource.
6. Decision:
   - If `currentAllocation + podRequest ≤ ceiling` for **all** resources → **Admit**.
   - If `currentAllocation + podRequest > ceiling` for **any** resource → **Deny**
     with a message listing all violated resources and figures.

### Admission Decision States

```
                    ┌─────────────────────┐
                    │  AdmissionReview     │
                    │  received            │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │  Deserialise        │──── failure ──→ DENY (malformed)
                    │  AdmissionReview    │
                    └──────────┬──────────┘
                               │ ok
                    ┌──────────▼──────────┐
                    │  Read cached        │──── stale/missing ──→ DENY (capacity
                    │  Allocation CRD     │                     data unavailable)
                    └──────────┬──────────┘
                               │ fresh
                    ┌──────────▼──────────┐
                    │  Extract pod        │──── parse failure ──→ DENY (resource
                    │  resource requests  │                      quantity error)
                    └──────────┬──────────┘
                               │ ok
                    ┌──────────▼──────────┐
                    │  Budget check:      │
                    │  projected ≤ ceiling?│─── any over ──→ DENY (over budget,
                    └──────────┬──────────┘                  with figures)
                               │ all within
                    ┌──────────▼──────────┐
                    │  ADMIT              │
                    └─────────────────────┘

  Timeout (any point) ──────────────→ DENY (timeout)
  Internal error / panic ───────────→ DENY (internal error)
  Unknown error type ───────────────→ DENY (by default, Principle III)
```

### 4. Budget Calculation (core algorithm)

```
Given:
  totalAllocatableCPU  (from ClusterCapacity status, milli-CPUs)
  totalAllocatableMem  (from ClusterCapacity status, bytes)
  budgetPercent        (from Allocation spec, 0–100)
  currentAllocatedCPU  (from Allocation status, milli-CPUs)
  currentAllocatedMem  (from Allocation status, bytes)
  podRequestCPU        (sum of incoming pod's container requests, milli-CPUs)
  podRequestMem        (sum of incoming pod's container requests, bytes)

Compute:
  ceilingCPU  = floor(totalAllocatableCPU * budgetPercent / 100)
  ceilingMem  = floor(totalAllocatableMem * budgetPercent / 100)
  projectedCPU = currentAllocatedCPU + podRequestCPU
  projectedMem = currentAllocatedMem + podRequestMem

Decision:
  if projectedCPU > ceilingCPU  → DENY (CPU over budget)
  if projectedMem > ceilingMem  → DENY (memory over budget)
  else                          → ADMIT

  (Both resources checked independently. If both exceed, both are reported.)
```

**Boundary semantics** (from spec edge cases):
- `projected == ceiling` → ADMIT (ceiling is inclusive).
- `projected == ceiling + 1` → DENY (over ceiling).
- `budgetPercent == 0` → ceiling = 0 → any pod with > 0 requests is DENIED.
- `budgetPercent == 100` → ceiling = totalAllocatable → only genuine
  overcommit beyond physical capacity is DENIED.
- `totalAllocatable == 0` (zero nodes) → ceiling = 0 → any pod with > 0
  requests is DENIED.

### 5. Resource Quantity Model

Kubernetes resource quantities are parsed into integer internal representation:

| Resource | Kubernetes format | Internal type | Unit |
|----------|------------------|---------------|------|
| CPU | `"500m"` (500 millicores), `"2"` (2 cores) | `i64` | milli-CPUs |
| Memory | `"1Gi"` (2³⁰ bytes), `"512Mi"`, `"1073741824"` | `i64` | bytes |

**Parsing rules** (per Kubernetes `resource.Quantity`):
- CPU: if suffix is `m`, value is in millicores. Otherwise, value is in cores
  → multiply by 1000 for milli-CPUs.
- Memory: suffix determines multiplier:
  - SI: `k` (10³), `M` (10⁶), `G` (10⁹), `T` (10¹²), `P` (10¹⁵) — powers of 1000
  - IEC: `Ki` (2¹⁰), `Mi` (2²⁰), `Gi` (2³⁰), `Ti` (2⁴⁰), `Pi` (2⁵⁰) — powers of 1024
- No suffix: value is in base units (millicores for CPU, bytes for memory).

**Pod request extraction** (FR-005):
For each container in `pod.spec.containers` (+ `initContainers`):
1. Read `resources.requests.cpu` and `resources.requests.memory`.
2. If `requests` is missing but `limits` is present: `requests = limits`
   (Kubernetes defaulting convention).
3. If both are missing: request = 0 for that resource.
4. Sum across all containers.

Init containers: the maximum of (sum of regular containers, max init container)
is the effective request, because init containers run sequentially (the node
must fit the largest single init container). This matches the
kube-scheduler's model.

## Metrics

Defined in research.md R10. The data model ties metrics to CRD status fields:

| Metric | Source | Type |
|--------|--------|------|
| `capacity_admission_verdicts_total{resource,verdict}` | webhook handler | Counter |
| `capacity_admission_decision_duration_seconds` | webhook handler | Histogram |
| `capacity_admission_capacity_freshness_seconds` | `Allocation.status.lastUpdated` | Gauge |
| `capacity_admission_allocation_ratio{resource}` | `Allocation.status.utilization_*` | Gauge |
| `capacity_admission_total_allocatable{resource}` | `ClusterCapacity.status` | Gauge |
| `capacity_admission_current_allocation{resource}` | `Allocation.status.allocated*` | Gauge |
| `capacity_admission_ceiling{resource}` | `Allocation.status.ceiling*` | Gauge |

Labels: `resource` ∈ `{cpu, memory}`, `verdict` ∈ `{allow, deny, error}`.
