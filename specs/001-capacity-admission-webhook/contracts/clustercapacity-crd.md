# Contract: ClusterCapacity CRD

**Phase**: 1 (Design) | **Date**: 2026-07-26

Defines the `ClusterCapacity` custom resource — the supply-side state written
by the Node Capacity Controller and read by the Allocation Controller.

## Spec

The spec is empty. This CRD exists to carry controller-computed status; it has
no user-configurable fields.

```yaml
spec: {}
```

---

## Status

Written by the Node Capacity Controller by summing
`node.status.allocatable` across all nodes in the cluster.

```yaml
status:
  totalAllocatableCPUMilli: 320000   # 320 cores
  totalAllocatableMemoryBytes: 515396075520   # 480 GiB
  nodeCount: 12
  lastUpdated: "2026-07-26T14:32:01Z"
```

| Field | Type | Description |
|-------|------|-------------|
| `totalAllocatableCPUMilli` | int64 | Sum of `node.status.allocatable.cpu` across all nodes, in milli-CPUs. |
| `totalAllocatableMemoryBytes` | int64 | Sum of `node.status.allocatable.memory` across all nodes, in bytes. |
| `nodeCount` | int32 | Number of nodes included in the sum. |
| `lastUpdated` | string (RFC 3339) | Timestamp of the last recomputation. Used by the webhook for freshness checks. |

---

## Controller Behaviour

The Node Capacity Controller:
1. Runs a `kube::runtime::reflector` on `Api::<Node>::all(client)`.
2. On every node event (Added/Modified/Deleted), recomputes the aggregate.
3. Patches the `cluster-capacity` CRD's `.status` subresource via
   `Api::<ClusterCapacity>::patch_status`.
4. Updates `lastUpdated` on every write.

**RBAC**: The controller's service account requires:
- `get`, `list`, `watch` on `nodes` (core/v1).
- `get`, `list`, `watch`, `update`, `patch` on `clustercapacities`
  (the `.status` subresource).
